# 校园网自动登录 2.0（Dr.COM / 哆点）

Windows 下的校园网 Portal 自动登录工具。2.0 把「自动登录」和「网络监控面板」合并成**一个单文件 exe**：
双击就能用，没有 PowerShell 脚本、不需要管理员权限、不需要安装任何运行时
（程序会顺手多起一个独立的守护小进程，主程序崩溃或卡死时把它自动拉回来）。

## 它解决什么问题

校园网账号隔几个小时会被踢下线，人不在电脑前就一直断网。2.0 的做法是：

- **网络正常时几乎不发请求**：默认每 20 秒做一次本地探测（先做**内容校验**：真的取回指定网页文本，再用 TCP / ICMP 兜底），
  平时**完全不碰 Portal**；在线时最多每 2 分钟只读核对一次 Portal 会话；
- **掉线发现得快**：订阅系统网络变化事件（网线插拔 / WiFi 切换 / IP 变化）后 1 秒内复检一次；
  「内容校验没过」按异常节奏复探，并每 20 秒向 Portal 求证一次，所以被踢下线后通常 1 分钟内就能开始重连；
- **断网时秒级重连**：所有探测目标**同时**跑（整轮耗时约等于单条目标的超时），
  HTTP 目标另有 3 秒的独立超时，连续几轮都不通才去查 Portal 并自动登录——完全断网时
  从发现到提交登录通常十几秒，而不是以前那种几十秒；
- **确认恢复不空等**：距上次登录不足 60 秒（风控硬性最小间隔）时，程序**每 5 秒只做本地探测**，
  不查 Portal、也不会登录；网络一恢复就立刻确认在线。老写法会让工作线程睡满剩余间隔——
  本机实测那段 33 秒空窗，正是「其实已经能上网，界面却还在重连」的元凶；
- **提交登录后确认得快**：先做一次 0 延迟的本地内容校验，再按 2 / 3 / 4 / 5 / 6 / 3 秒**加密复检**
  （累计 2/5/9/14/20/23 秒，每档只发一次**只读** `chkstatus`）。本机 50 次自然掉线实测：
  旧阶梯下 29 次都拖到 +20 秒才由 Portal 确认，加密后中位约 **+14 秒**；
- **不会被「假在线」骗到**：有的校园网关会替任意 TCP 连接代答握手（连不存在的地址也 0 ms「连上」），
  所以判断在线必须拿到预期网页内容；只要内容校验没过，就立刻向 Portal 求证并重连；
- **不触发风控**：登录前二次确认、两次登录至少间隔 60 秒、每小时最多 12 次；遇到限流或
  「账号已在别处在线」（`userid error2`）只记下原因、本次不再重试，按上面的节奏继续尝试，不会反复顶号；
- **看得见**：托盘图标颜色跟着状态变，仪表盘上有 IP／网关／DNS／延迟／丢包、运行统计和实时日志；
- **不误报、不误发**：只有 Portal 明确回答「在线」才算登录成功（状态接口不可达记为「待确认」并继续复检）；
  登录请求禁止跟随跳转、响应必须来自同一台主机；`config.json` 损坏或探测目标全写错时会停下来提示，
  而不是拿着默认地址或坏配置继续登录。
- **不往磁盘里写密码**：日志与状态文件在落盘前统一脱敏（密码一律 `***`，账号打码成 `251******`），
  即使某校 Portal 把提交的表单回显在错误页里也一样；「复制诊断信息」读的就是这两处，粘贴出去同样干净。

已知限制：本工具按**明文**提交密码（相当于 `en_md5=0`）。个别学校要求 `en_md5=1`
（`upass = MD5(PID+密码+CALG)+CALG+PID`），这类 Portal 会一直回 `userid error2 / 密码错误`，
日志里会有一条明确提示；目前请改用学校官方客户端。

## 下载与首次使用

1. 到 [Releases](../../releases) 下载附件 `CampusNet-v2.0.0.exe`（2.0 的发布只有这一个文件）。
   附件名里的版本号和标签名一致（标签 `v2.0.0` → 附件 `CampusNet-v2.0.0.exe`），文件名不影响使用、
   不用改名；源码在仓库 `main` 分支，详细说明见 [docs/使用说明.md](docs/使用说明.md)。
2. 双击下载到的那个 exe。首次运行可能出现 Windows SmartScreen 提示（程序没有花钱买数字签名），
   点「更多信息 → 仍要运行」即可。
3. 在窗口右上「账号」卡片里填校园网账号和密码，点 **保存账号密码**。
   密码用 Windows DPAPI 加密，只有当前 Windows 用户能解密，不会明文落盘。
4. 点 **安装**：程序会把自己复制到 `%LOCALAPPDATA%\Programs\CampusNet\`、创建开始菜单快捷方式并开启开机自启。
5. 关闭窗口即可，程序会收进右下角托盘继续守护；要彻底退出请右键托盘图标 → 退出（会二次确认）。

> 如果机器上还留着 1.x 的 PowerShell 版，程序会在「程序」卡片里提示，点 **清理旧版残留** 一键删除
> 旧的计划任务与脚本目录（只有这一步需要一次 UAC 确认）。

## 工作原理

```
        ┌──────────── 常驻进程（托盘） ────────────┐
        │ 触发：网络变化事件 / 休眠唤醒 / 解锁 / 定时 │
        └───────────────────┬──────────────────────┘
                            ▼
   本地探测第一步：内容校验（真的取回指定网页文本，或核对状态码 204）
                    ┌───────┴────────┐
               内容对得上          对不上（或被代答）
                    │                │
              状态=在线，结束      GET /drcom/chkstatus 求证
             （0 个 Portal 请求）   ┌───────┴────────┐
               每 2 分钟只读核对   result=1         result=0 / 探测不通
              一次 Portal 会话        │                │
                                  本机连续 60 秒   等 1 秒二次确认 → POST /drcom/login
                                  不通才注销重登           │
                                                  登录成功 → 复探确认
```

- 正常联网时**每小时约 180 次本地探测**（默认每 20 秒一次），Portal 只读核对约 30 次（默认每 2 分钟一次），
  登录请求为 **0**；
- 异常时每 5 秒探测一次，尽快把网络拉回来；**「TCP 通、内容校验没过」也按异常节奏复探**，
  所以被踢下线后十几秒内就会去核对 Portal 并自动登录；
- 探测不通但 Portal 显示账号在线时，按“兜底巡检”节奏复查（默认每 300 秒）；
- 内容校验目标写在 `ProbeTargets` 里，格式 `http:主机/路径|期望文本`（`https:` 同样支持）、
  `http:主机/路径|204`（只认状态码，专治「被劫持时返回 200 门户页」），
  也可以两者都要：`http:主机/路径|期望文本|204`；
  只有 HTTP 2xx **且**响应体包含期望文本才算通过，3xx 一律算失败（被跳到登录页正是未认证的特征）；
- 内容校验**第一次没过时会立刻并行补测一轮**（此时 TCP 已经证明能连，多半只是单次超时）：
  补测通过就按在线处理，补测也失败才去核对 Portal——既不误判，也不会漏掉真正的掉线；
- 登录接口回了成功、但**状态接口同时不可达**时，不会当成登录成功（那正是
  「Portal 掉线 + 其实没联上网」的样子），而是记为「待确认」继续按异常节奏复检；
- 延迟显示的是**按配置顺序第一个成功目标**的耗时，不会再被 0 ms 的代答目标带偏；
- Portal 回「账号已在别处在线 / 密码错误」这类业务提示时，程序**完全忽略**它：
  只记一行日志与「已忽略提示」计数，随后做几次轻量复检，网络真的通了就立刻算成功；
- 登录前的二次确认**先做一次纯本地内容校验**（不发 Portal 请求）：本地已经能上网就直接判定无需登录，
  连 `chkstatus` 都不查；确认不通才等 **1 秒**（`LoginConfirmDelaySec`）并查一次 Portal 状态，
  两次都判离线才提交登录。所以「发现离线 → 提交登录」通常只要 1 秒左右；
- 登录提交后**先立刻做一次本地内容校验**（0 延迟、不发 Portal 请求），再按 **+2 / +5 / +9 / +14 / +20 / +23 秒**复检：
  登录瞬间生效时不必先白等，Portal 稍后才认账的情况也能早几秒确认（每档只发一次只读 `chkstatus`）；
- 被最小间隔（默认 60 秒）拦下时**不会干等**：等待期内每约 5 秒只做本地探测，
  网络一恢复立刻确认（日志写「最小间隔等待期内检测到网络恢复」），这段时间**一个 Portal 请求都不发**；
- 本机连续 60 秒不通、Portal 却坚持说账号在线（典型的残留会话）时，
  程序会自动**注销 + 重新登录**一次，不需要手动点「立即重连」；
- 后台有**守护进程**（独立小进程，每 30 秒看一次）：主程序崩溃或卡死会自动被拉起来；
  用户在托盘里点「退出」时它会一起收工，不会跟你抢着启动；
- 插拔网线、切换 WiFi、IP 变化都会立即触发一次评估（订阅系统网络变化事件，1 秒防抖），
  不必等到下一个探测周期。

## 数据与隐私

所有数据都在 `%LOCALAPPDATA%\CampusNet\`：

| 文件 | 内容 |
| --- | --- |
| `credentials.dat` | 账号 + DPAPI 加密后的密码（只有当前 Windows 用户能解密） |
| `config.json` | Portal 地址、探测节奏、风控闸门等配置（首次运行自动生成） |
| `state.json` | 当前状态快照（在线与否、最近结果、最近会话核对及其来源、累计检查次数）；状态没有变化时最多每 60 秒才写一次盘 |
| `login.log` | 运行日志，超过 5 MB 自动滚动为 `login.log.old` |
| `crash.log` | 崩溃现场（只有真出过问题时才会有），含完整堆栈 |
| `watchdog.log` | 守护任务的动作日志（什么时候拉起过、为什么） |

程序不会上传任何数据，除校园网 Portal 外只做本地探测；Portal 请求显式绕过系统代理。

## 命令行（排障 / 自动化）

双击是普通用法，命令行参数用于排查和脚本化：

```
CampusNet.exe                 打开仪表盘并开始守护（也是双击的默认行为）
CampusNet.exe --tray          只进托盘，不弹窗口（开机自启用的就是它）
CampusNet.exe --status        打印当前状态一行行摘要
CampusNet.exe --diagnose      打印完整诊断信息（加 --with-log 附带日志尾部）
CampusNet.exe --clear-log     清空运行日志（等价于界面上的「清空日志」按钮）
CampusNet.exe --watchdog      守护自检并（必要时）把后台拉起来
CampusNet.exe --watchdog-loop 守护进程主循环（常驻，由主程序自动启动）
CampusNet.exe --relogin       立即注销并重新登录（等这一轮真正跑完再退出，最长 120 秒）
CampusNet.exe --once          前台跑一轮检查后退出（用于验证）
CampusNet.exe --run-seconds N 前台跑 N 秒后退出
CampusNet.exe --install       安装到用户目录并开启开机自启
CampusNet.exe --uninstall     卸载（加 --delete-data 连数据一起删；卸载后程序会自动退出，
                              由独立清理进程删除程序文件，删不掉则下次重启后消失）
CampusNet.exe --uninstall --check-only
                              只打印卸载计划（删哪些文件、文件什么时候消失），不删任何东西
CampusNet.exe --set-credentials <账号> [--password-stdin]
CampusNet.exe --selftest      界面自检（构建窗口、刷新一次后退出）
CampusNet.exe --version
```

退出码：`0` 成功 / `1` 失败 / `2` 配置或凭据有问题。

## 高级配置

`%LOCALAPPDATA%\CampusNet\config.json`（界面「高级设置」也能改，改完立即生效）：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `PortalHost` | `10.66.209.2` | Portal 地址（可带端口；写成 `https://…` 也可以） |
| `PortalScheme` | `http` | Portal 协议：`http` / `https` |
| `StatusPath` / `LoginPath` / `LogoutPath` | `/drcom/chkstatus` 等 | 接口路径 |
| `OnlineProbeSeconds` | `20` | 网络正常时的探测间隔 |
| `OfflineProbeSeconds` | `5` | 探测异常后的复检间隔 |
| `UpstreamProbeSeconds` | `300` | 「本机探测不通、Portal 显示在线」时的兜底巡检间隔 |
| `ProbeTargets` | 3 个内容校验目标 + 1 个 TCP 目标 | 判断「能不能上网」的目标（**并行执行**）；`http:主机/路径\|期望文本`、`http:主机/路径\|204`、`http:主机/路径\|文本\|204` 为内容校验，`tcp:主机:端口`、`icmp:主机` 为兜底 |
| `ProbeTimeoutMs` / `HttpProbeTimeoutMs` | `1500` / `3000` | TCP·ICMP 与 HTTP 各自的单目标超时（毫秒） |
| `ConfirmAttempts` / `ConfirmGapMs` | `2` / `500` | 判定断网前的并行复检轮数与间隔 |
| `LoginConfirmDelaySec` | `1` | 登录前二次确认的等待秒数（确认前先做一次纯本地内容校验，本地能上网就直接跳过登录） |
| `LoginMinIntervalSeconds` | `60` | 两次登录之间的硬性最小间隔 |
| `LoginHourlyLimit` | `12` | 每小时登录次数上限 |
| `RetryCount` | `1` | 一次触发内最多提交几次登录；**每次提交前都会重新检查最小间隔与每小时上限**，调大也不会绕过风控 |
| `SessionCheckSeconds` | `120` | 在线时只读核对 Portal 会话的间隔（`0` = 关闭）。这是「被踢下线」最主要的发现途径，调小恢复更快，调大请求更少 |
| `StuckReloginSeconds` | `60` | 本机连续不通但 Portal 说在线，超过这个秒数就自动注销重登（`0` = 关闭） |
| `ConfigVersion` | `7` | 配置结构版本（自动迁移：60 秒探测 → 20 秒；旧的默认探测列表 → 新的四条默认；3 轮/1000 毫秒复检 → 2 轮/500 毫秒；会话核对 300 秒 → 120 秒；登录前确认 3 秒 → 1 秒） |
| `StaticFields` | `0MKKey=123456` 等 | 登录表单固定字段（不同学校可能不同） |

## 从 1.x 升级

- 1.x 的计划任务 `CampusAutoLogin`、脚本目录 `C:\CampusAutoLogin`、旧数据目录
  `%LOCALAPPDATA%\CampusAutoLogin` 都可以由 2.0 的「清理旧版残留」处理（旧数据目录默认保留，可手动删除）。
- 账号密码不会自动迁移，重新输入一次即可。
- 1.x 的历史版本仍在 Releases 里，可以随时回退；1.x 的收官版本是 **1.9.0**（功能冻结，仍可下载）。

## 源码与构建

```
src/CampusNet/           C# 源码（App.xaml、MainWindow.xaml、Core/*.cs、UI/TrayIcon.cs、Assets/app.ico）
build/Build-CampusNet.ps1  一键编译：产出 dist\CampusNet.exe 与 SHA256，并跑一遍端到端测试
build/Test-CampusNet.ps1   端到端测试：本地假 Portal 验证探测、登录、风控闸门
build/FakePortal.ps1       测试用的假 Portal（只监听 127.0.0.1）
dist/CampusNet.exe       已编译好的单文件 exe（随仓库提交，也是发布附件）
docs/                    协议说明、故障排查、使用说明

构建要求：Windows + .NET SDK（或 Visual Studio 的 MSBuild），目标框架 `net48`，零第三方 NuGet 依赖。

powershell -ExecutionPolicy Bypass -File build\Build-CampusNet.ps1          # 编译 + 测试
powershell -ExecutionPolicy Bypass -File build\Build-CampusNet.ps1 -SkipTests
```
