# 校园网自动登录 2.1.2（Dr.COM / 哆点）

Windows 下的校园网 Portal 自动登录工具。**一个单文件 exe 同时管两件事：自动登录 + 网络状态面板。**
双击就能用：没有 PowerShell 脚本、不需要管理员权限、不需要安装任何运行时。

[![Windows](https://img.shields.io/badge/Windows-10%20%2F%2011-0078D6)](https://www.microsoft.com/windows/)
[![.NET Framework](https://img.shields.io/badge/.NET%20Framework-4.8-512BD4)](https://dotnet.microsoft.com/)

## 快速开始

1. 到 [Releases](../../releases) 下载 `CampusNet-v2.1.2.exe`。2.x 的发布**只有这一个文件**：不用解压、不用改名
   （附件名里的版本号就是标签名，源码在仓库 `main` 分支）。
2. 双击运行。首次启动可能弹 SmartScreen（程序没有购买数字签名），点「更多信息 → 仍要运行」。
3. 在窗口右上「账号」卡片填校园网账号和密码，点 **保存账号密码**。密码用 Windows DPAPI 加密，只有当前 Windows 用户能解开。
4. 点 **安装**：程序把自己复制到 `%LOCALAPPDATA%\Programs\CampusNet\`、创建开始菜单快捷方式、开启开机自启。
5. 关掉窗口就行，程序收进右下角托盘继续守着。要彻底退出：右键托盘图标 → **退出**（会二次确认）。

> 机器上若还留着 1.x 的 PowerShell 版，「程序」卡片会提示，点 **清理旧版残留** 一键删掉旧计划任务与脚本目录
> （只有这一步需要一次 UAC）。

## 主要特性

**平时几乎不打扰**

- 默认每 15 秒做一次本地探测，全程**不发 Portal 请求**；在线时每 120 秒只读核对一次会话；
- 判定「能不能上网」以**内容校验**为准 —— 真的取回指定网页文本，或核对 204 状态码，TCP / ICMP 只做兜底。
  有的校园网关会替任意 TCP 连接代答握手（连不存在的地址也能 0 ms「连上」），只看握手会被骗；
- 延迟显示**按配置顺序第一个成功目标**的耗时，不会被 0 ms 的代答目标带偏。

**掉线发现得快**

- 订阅系统网络变化事件（网线插拔 / WiFi 切换 / IP 变化），1 秒防抖后立刻复检，不必等下一个探测周期；
- 内容没过就按异常节奏复探（默认每 3 秒），**「TCP 通但内容校验没过」同样算异常**：
  连续 1 轮拿不到内容就去核对 Portal（之前还有一次立即补测，单次抖动会被挡掉），
  两次核对之间至少隔 10 秒；
- 在线时每 120 秒只读核对一次 Portal 会话（`SessionCheckSeconds`），Portal 说不在线就直接进入登录流程 ——
  这是「被踢下线」最主要的发现途径。

**确认恢复不空等**

- 登录前先做一次**纯本地**内容校验：本地已经能上网就不登录，连 `chkstatus` 都不查；确认不通才等 1 秒做二次确认再提交。
  所以「发现离线 → 提交登录」通常只要 1 秒左右；
- **残留会话不再干等**：登录被回「账号已在别处在线」且 3 秒内本机还是上不了网，就**先注销、等 3 秒、再登录一次** ——
  真机 6/6 样本都在提交后 5 秒内恢复（老做法要等 Portal 用新登录顶掉旧会话，中位 22 秒）；
- 提交登录后按 **1 秒一档、共 30 档**的密集窗口复检：每档一次本机内容校验，每 3 档加一次只读 `chkstatus`；
  候选信号出现后还要用一次完整探测复核，**只有本机真的能取回内容才算恢复**。

- **2.1.3-pre.1 起不再有限速**：登录只剩「登录前 1 秒二次确认」这一道闸门，
  Portal 明确回 `waitsec`（请求过于频繁）时按它给的秒数暂停；一次恢复动作最多提交 2 次登录；
- Portal 回「账号已在别处在线 / 密码错误」这类业务提示时**完全忽略**：不算失败、不写「最近错误」，
  只限频记一行日志，然后靠本机内容校验判断到底有没有恢复；
- 登录接口说成功、但本机内容始终取不回来时记为「待确认」，不会假装成功然后长时间不再重试；
- 登录请求禁止跟随跳转、响应必须来自同一台主机；`config.json` 损坏或探测目标全写错时会停下来提示，
  而不是拿坏配置继续登录。

**看得见、量得出**

- 托盘图标颜色跟着状态变；面板上有 IP / 网关 / 网卡 / DNS / 延迟 / 丢包、最近 60 次探测的延迟柱状图、运行统计和实时日志；
- 「今日登录 N 次 / 提交 M 次」跨零点自动重算；「恢复耗时：上次 N 秒 / 本次中位 M 秒」只留在内存里，退出即清空；
- 后台多起一个独立的**守护小进程**：主程序崩溃或卡死会被自动拉回来，从托盘「退出」时一起收工。

**不往磁盘里写密码**

- 日志与状态文件在落盘前统一脱敏：密码一律 `***`，账号打码成 `251******`。
  即使某校 Portal 把提交的表单回显在错误页里也一样；
- 「复制诊断信息」读的就是这两处，贴到群里同样干净。

## 界面

| 区域 | 内容 |
| --- | --- |
| 顶部状态横幅 | 在线 / 重连中 / 已暂停 / 未配置，颜色一眼可辨 |
| 网络状态 | 本机 IP、网关、网卡、DNS、延迟、丢包，以及最近 60 次探测的延迟柱状图 |
| 账号 | 账号密码输入与保存（空框有灰色提示；密码留空表示只改账号，不会清掉已存的密码） |
| 运行统计 | 最近探测 / 最近登录、最近结果、今日登录、下次探测、会话校验、上次恢复 / 恢复耗时、最近错误 |
| 程序 | 开机自启开关、安装 / 卸载、打开数据目录、清理旧版残留、**高级设置**（独立窗口，改完即保存，没有「保存」按钮） |

## 工作原理

```
        ┌──────────── 常驻进程（托盘） ────────────┐
        │ 触发：网络变化事件 / 休眠唤醒 / 解锁 / 定时 │
        └───────────────────┬──────────────────────┘
                            ▼
   本地探测：内容校验（真的取回指定网页文本，或核对状态码 204）
                    ┌───────┴────────┐
               内容对得上          对不上（或被网关代答）
                    │                │
              状态=在线，结束      GET /drcom/chkstatus 求证
              （0 个 Portal 请求）  ┌───────┴────────┐
              每 120 秒只读核对    result=1         result=0 / 探测不通
               一次 Portal 会话        │                │
                                   本机连续 15 秒   先本地内容校验 → 等 1 秒二次确认 → POST /drcom/login
                                   不通才注销重登           │
                                          │        被回「已在别处在线」→ 注销 → 等 3 秒 → 再登录一次
                                          │                 │
                                          └──────────► 1 秒一档复检 30 档 → 本机内容确认恢复
```

请求预算（默认配置，每一项都能在「高级设置」里改）：

| 情形 | 本地探测 | 只读会话核对 | 登录请求 |
| --- | --- | --- | --- |
| 正常在线 | 约 240 次/小时（每 15 秒） | 约 30 次/小时（每 120 秒） | 0 |
| 内容校验没过 | 每 3 秒一次 | 最多每 10 秒一次 | 0 |
| 一轮掉线 | 每 3 秒一次 | 整轮最多 14 次 | 1~2 |

其他细节：

- 探测目标写在 `ProbeTargets` 里，格式 `http:主机/路径|期望文本`（`https:` 同样支持）、
  `http:主机/路径|204`（只认状态码，专治「被劫持时返回 200 门户页」），也可以两者都要：`http:主机/路径|期望文本|204`。
  只有 HTTP 2xx **且**响应体包含期望文本才算通过，3xx 一律算失败（被跳到登录页正是未认证的特征）；
- 所有探测目标**并行**执行，整轮耗时约等于单条目标的超时，HTTP 目标另有独立超时；
- 内容校验第一次没过会立刻并行补测一轮（此时 TCP 已经证明能连，多半只是单次抖动），补测也失败才去核对 Portal；
- 探测不通但 Portal 显示账号在线时，按「兜底巡检」节奏复查（默认每 300 秒，`UpstreamProbeSeconds`）；
- 本机连续 15 秒不通、Portal 却坚持说账号在线（典型的残留会话）时，程序会自动**注销 + 重新登录**一次，
  不需要手动点「立即重连」；登录被回「已在别处在线」时也会走同一条路；
- 探测与登录的每一步都会写进日志：哪个目标通、哪一步花了多少秒，事后都能查。
- **实测量级**（真实校园网，9067 行日志 / 09-18 → 09-26）：从被踢到提交登录中位约 1 秒；
  从提交到确认恢复，直接登录的 88 次成功里中位 **22 秒**、**57% 落在 20 秒以后** ——
  时间几乎都花在「等 Portal 用新登录顶掉旧会话」上；而 6 次「先注销再登录」**全部**在提交后 5 秒内恢复。

## 数据与隐私

所有数据都在 `%LOCALAPPDATA%\CampusNet\`：

| 文件 | 内容 |
| --- | --- |
| `credentials.dat` | 账号 + DPAPI 加密后的密码（只有当前 Windows 用户能解密） |
| `config.json` | Portal 地址、探测节奏、风控闸门等配置（首次运行自动生成） |
| `state.json` | 状态快照（在线与否、最近结果、最近会话核对及来源等）；状态没变化时最多每 60 秒写一次盘 |
| `login.log` | 运行日志，超过 5 MB 自动滚动为 `login.log.old` |
| `crash.log` | 崩溃现场（只有真出过问题时才会有），含完整堆栈 |
| `watchdog.log` | 守护进程的动作日志（什么时候拉起过、为什么） |

程序不上传任何数据；除校园网 Portal 外只做本地探测。Portal 请求显式绕过系统代理。

## 命令行（排障 / 自动化）

双击是普通用法，命令行参数用于排查与脚本化：

```
CampusNet.exe                 打开仪表盘并开始守护（也是双击的默认行为）
CampusNet.exe --tray          只进托盘，不弹窗口（开机自启用的就是它）
CampusNet.exe --status        打印当前状态摘要
CampusNet.exe --diagnose      打印完整诊断信息（加 --with-log 附带日志尾部）
CampusNet.exe --clear-log     删除历史日志文件 login.log / login.log.old，并留下一行「日志已清空」
                              （唯一会删日志文件的入口；界面上的「清除显示」只清空窗口显示）
CampusNet.exe --watchdog      守护自检并（必要时）把后台拉起来
CampusNet.exe --watchdog-loop 守护进程主循环（常驻，由主程序自动启动）
CampusNet.exe --relogin       立即注销并重新登录（等这一轮真正跑完再退出，最长 120 秒）
CampusNet.exe --once          前台跑一轮检查后退出（用于验证）
CampusNet.exe --run-seconds N 前台跑 N 秒后退出
CampusNet.exe --install       安装到用户目录并开启开机自启
CampusNet.exe --uninstall     卸载（加 --delete-data 连数据一起删；卸载后程序会自动退出，
                              由独立清理进程删除程序文件，删不掉则下次重启后消失）
CampusNet.exe --uninstall --check-only
                              只打印卸载计划（删哪些文件、什么时候消失），不删任何东西
CampusNet.exe --set-credentials <账号> [--password-stdin]
CampusNet.exe --selftest      界面自检（构建窗口、刷新一次后退出）
CampusNet.exe --version
```

退出码：`0` 成功 / `1` 失败 / `2` 配置或凭据有问题。

## 高级配置

`%LOCALAPPDATA%\CampusNet\config.json`（界面「高级设置」也能改，改完立即生效）：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `PortalHost` | `10.66.209.2` | Portal 地址（可带端口；写成 `https://…` 也可以） |
| `PortalScheme` | `http` | Portal 协议：`http` / `https` |
| `StatusPath` / `LoginPath` / `LogoutPath` | `/drcom/chkstatus` 等 | 接口路径 |
| `OnlineProbeSeconds` | `15` | 网络正常时的探测间隔 |
| `OfflineProbeSeconds` | `3` | 探测异常后的复检间隔（「疑似掉线复测」也跟着它，内部下限 5 秒） |
| `UpstreamProbeSeconds` | `300` | 「本机探测不通、Portal 显示在线」时的兜底巡检间隔 |
| `ProbeTargets` | 3 个内容校验目标 + 1 个 TCP 目标 | 判断「能不能上网」的目标（**并行执行**），格式见上文 |
| `ProbeTimeoutMs` / `HttpProbeTimeoutMs` | `1500` / `3000` | TCP·ICMP 与 HTTP 各自的单目标超时（毫秒） |
| `ConfirmAttempts` / `ConfirmGapMs` | `2` / `500` | 判定断网前的复检轮数与间隔 |
| `LoginConfirmDelaySec` | `1` | 登录前二次确认的等待秒数（确认前先做一次纯本地内容校验，本地能上网就直接跳过登录） |
| `RetryCount` | `1` | 一次触发内最多提交几次登录。2.1.3-pre.1 起删除了最小间隔与每小时上限，每次提交都排在 30 秒复检窗口之后，不会秒级连打 |
| `SessionCheckSeconds` | `120` | 在线时只读核对 Portal 会话的间隔（`0` = 关闭）。这是「被踢下线」最主要的发现途径，调小恢复更快，调大请求更少 |
| `StuckReloginSeconds` | `15` | 本机连续不通但 Portal 说在线，超过这个秒数就自动注销重登（`0` = 关闭） |
| `StaticFields` | `0MKKey=123456` 等 | 登录表单固定字段（不同学校可能不同） |
| `ConfigVersion` | `10` | 配置结构版本，自动迁移：只改「等于旧默认值」的那一份（2.1.3-pre.1 把在线 20 → 15、异常 5 → 3、残留重登 60 → 15；此前还有 2.1.2 的节奏回滚、登录前确认 3 → 1 秒、旧默认探测列表 → 新的四条）；自己填过的值一律保留 |

## 已知限制

- 本工具按**明文**提交密码（相当于 `en_md5=0`）。个别学校要求 `en_md5=1`
  （`upass = MD5(PID+密码+CALG)+CALG+PID`），这类 Portal 会一直回 `userid error2 / 密码错误`，
  日志里会有一条明确提示；目前请改用学校官方客户端。
- 一直显示在线却上不了网、或者日志里反复出现「内容校验未通过」，见 [故障排查](docs/TROUBLESHOOTING.md)。

## 从 1.x 升级

- 1.x 的计划任务 `CampusAutoLogin`、脚本目录 `C:\CampusAutoLogin`、旧数据目录
  `%LOCALAPPDATA%\CampusAutoLogin` 都可以由 2.x 的 **清理旧版残留** 处理（旧数据目录默认保留，可手动删除）。
- 账号密码不会自动迁移，重新输入一次即可。
- 1.x 的历史版本仍在 Releases 里，可以随时回退；1.x 的收官版本是 **1.9.0**（功能冻结，仍可下载）。

## 源码与构建

```
src/CampusNet/             C# 源码（App.xaml、MainWindow.xaml、Core/*.cs、UI/TrayIcon.cs、Assets/app.ico）
build/Build-CampusNet.ps1  一键编译：产出 dist\CampusNet.exe、SHA256 与源码指纹，并跑一遍端到端测试
build/Test-CampusNet.ps1   端到端测试：本地假 Portal 验证探测、登录、限流暂停与今日统计
build/FakePortal.ps1       测试用的假 Portal（只监听 127.0.0.1）
dist/CampusNet.exe         已编译好的单文件 exe（随仓库提交，也是发布附件）
docs/                      协议说明、故障排查、使用说明
```

构建要求：Windows + .NET SDK（或 Visual Studio 的 MSBuild），目标框架 `net48`，零第三方 NuGet 依赖。

```powershell
powershell -ExecutionPolicy Bypass -File build\Build-CampusNet.ps1          # 编译 + 测试
powershell -ExecutionPolicy Bypass -File build\Build-CampusNet.ps1 -SkipTests
```
