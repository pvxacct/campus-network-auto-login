# 故障排查（校园网自动登录 2.0）

先做两件事：打开仪表盘看顶部状态横幅；点「复制诊断信息」把信息拿到手。
下面按症状给出处理办法。

## 1. 状态一直是「未配置 / 还没保存账号密码」

账号密码没保存或保存失败。在「账号」卡片重新填写后点 **保存账号密码**。
如果提示保存失败，检查 `%LOCALAPPDATA%\CampusNet\` 是否可写（例如被安全软件锁住）。

## 2. 一直显示「在线」但实际打不开网页（重要）

先看仪表盘「运行统计」里的 **探测方式** 一栏：

- 显示 **内容校验 + TCP 兜底** → 说明配置正常。如果这时还一直显示在线，就点「复制诊断信息」发出来，
  因为程序已经要求「真的取回指定网页文本」才算在线，出现这种矛盾多半是探测目标被学校网络特殊处理了；
- 显示 **仅 TCP 握手（可能被代答）** → 你（或旧配置）把 `ProbeTargets` 全设成了 `tcp:`。
  **有的校园网关会替任意 TCP 连接代答握手**（连不存在的地址也 0 ms「连上」），
  这种情况下程序永远判断不出掉线。请至少保留一个内容校验目标。

`ProbeTargets` 支持的写法：

```json
"ProbeTargets": [
  "http:www.msftconnecttest.com/connecttest.txt|Microsoft Connect Test",
  "tcp:223.5.5.5:443",
  "tcp:114.114.114.114:53"
]
```

| 写法 | 含义 |
| --- | --- |
| `http:主机/路径\|期望文本` | 内容校验：HTTP 2xx **且**响应体包含期望文本才算通过（`https:` 同样支持；3xx 一律算失败） |
| `tcp:主机:端口` | 只做 TCP 握手（便宜，但可能被网关代答） |
| `icmp:主机` | ping，很多网络禁 ICMP，只能当兜底 |

延迟显示的是**按配置顺序第一个成功目标**的耗时，不会再被 0 ms 的代答目标带到 0。
如果某个目标显示「（本地代答）」，说明它的 RTT 小于 5 ms，基本可以认定是本机/网关自己回应的。

另外，程序在线时默认每 5 分钟会做一次**只读**的会话核对（`SessionCheckSeconds`，`0` = 关闭），
核对结果会写进「运行统计 → 会话校验」。如果连它都显示「Portal 显示已离线」，
程序会立刻走登录流程——不需要你手动点「立即重连」。

## 3. 状态是「连不上校园网，等待网络恢复」

说明本地探测和 Portal 都不通。这时候程序不会去登录（登录也没用），会每 5 秒重试。检查：

- 网线是否插好 / Wi-Fi 是否连上；
- 是否连到了错误的网络（例如手机热点或其它 Wi-Fi）；
- 本机是否开着会拦截流量的代理软件（Clash、VPN 等）。程序自身访问 Portal 时已显式绕过系统代理，
  但代理的 TUN 模式仍可能影响局域网访问。

## 4. 状态是「本机探测不通，但 Portal 显示账号在线」

这是上游异常（Portal 认为你在线，但实际数据出不去），常见于校园网侧故障或网卡驱动异常。
程序会转成按“兜底巡检”节奏复查（`UpstreamProbeSeconds`，默认每 300 秒一次），不会重复登录顶掉自己的会话。
可以手动试试点「立即重连」，或重插网线 / 重启网卡。

## 5. 状态是「已触发频率上限」或「登录失败（账号已在别处在线）」

这两种情况都只是**本轮不再重试**，原因会写进仪表盘的「最近错误」和日志，程序会按节奏继续尝试：

- **Portal 明确限流（请求过于频繁）**：`error5 waitsec` / `Error code: 205`。程序会等过最小间隔
  （默认 60 秒）再试，并且每小时最多登录 12 次；如果频繁出现，说明同一账号在别处也在反复登录；
- **账号已在别处在线（`userid error2`）**：2.0.0-pre.3 起按需求**忽略**这个提示——
  不再当成特殊冲突，只做一次 2 秒复检（真在线就算成功），否则记为一次普通失败并在日志里提醒一次
  （`WarnOnce`，不会刷屏），随后按最小间隔与每小时上限继续尝试。

节奏可以在 `config.json` 里用 `LoginMinIntervalSeconds`（两次登录最小间隔，默认 `60` 秒）与
`LoginHourlyLimit`（每小时上限，默认 `12` 次）调整；界面上的「高级设置」也能改。

## 6. 登录失败，日志里有 `Msg=…` 与错误码

程序会把 Portal 返回的 `msga` 送到错误码接口翻译成中文，常见含义：

| 错误码 | 提示 | 处理 |
| --- | --- | --- |
| `userid error1` | 账号不存在 | 账号写错了，或不在该认证域 |
| `userid error2` | 密码错误 / 账号已在线 | 先确认密码；如果密码没错，就是账号被占用（见上一节） |
| `error5 waitsec <3` | 请求过于频繁 | 刚注销完又立刻登录，等几秒 |
| `Error code: 205` | System Error1 | 多为请求过于频繁，程序会等过最小间隔再试 |

## 7. 杀毒软件 / SmartScreen 拦截

exe 是用仓库源码现场编译、没有数字签名的程序，火绒、Defender 可能首次运行就拦。
处理办法：在拦截提示里选择「允许 / 信任」；火绒可以在「防护中心 → 信任区」把
`CampusNet.exe` 或 `%LOCALAPPDATA%\Programs\CampusNet\` 加进白名单。

## 8. 开机后没有自动运行

检查三点：

1. 仪表盘的 **开机自动运行** 勾选框是勾上的；
2. 注册表 `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` 里存在 `CampusNet` 项；
3. 任务管理器的「启动」页里 `CampusNet` 没有被禁用。

如果之前用「绿色版」直接运行，自启项指向的是那个临时路径，移动文件后需要重新勾一次自启（或点一次「安装」）。

## 9. 想临时停止自动登录

托盘右键 → **暂停 30 分钟**（到点自动恢复），或者托盘右键 → **退出**（不自动恢复，需要手动打开）。

## 10. 彻底卸载

仪表盘点 **卸载**：会关闭开机自启、删除快捷方式，并移除安装目录里的 exe（数据默认保留）。
要连数据一起删，卸载后手动删除 `%LOCALAPPDATA%\CampusNet\` 即可。

## 11. 需要更深入的排查

```powershell
# 当前状态一行行打印
CampusNet.exe --status

# 完整诊断（版本、路径、网络、配置、状态、旧版残留、日志尾部）
CampusNet.exe --diagnose --with-log

# 前台跑一轮完整检查（会真实探测，必要时登录）
CampusNet.exe --once

# 界面自检：构建窗口、刷新一次后退出
CampusNet.exe --selftest

# 清空运行日志（两个日志文件都清掉，只留一行「日志已清空」）
CampusNet.exe --clear-log
```

日志文件：`%LOCALAPPDATA%\CampusNet\login.log`（超过 5 MB 自动滚动为 `login.log.old`）。
界面上的「运行日志」卡片右上角也有 **清空日志** 按钮（会二次确认）。
高级设置里的输入框**改完即自动保存**（点开别处或按回车生效），没有单独的保存按钮；
填了超出范围的值会自动回退，并在下方显示该项目的允许范围。
协议层面的细节（接口、字段、编码、错误码来源）见 [Dr.COM ePortal 协议说明](DRCOM-PROTOCOL.md)。
