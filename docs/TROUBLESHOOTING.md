# 故障排查（校园网自动登录 2.1）

先做两件事：打开仪表盘看顶部状态横幅；点「复制诊断信息」把信息拿到手。
下面按症状给出处理办法。

## 1. 状态一直是「未配置 / 还没保存账号密码」

账号密码没保存或保存失败。在「账号」卡片重新填写后点 **保存账号密码**。
如果提示保存失败，检查 `%LOCALAPPDATA%\CampusNet\` 是否可写（例如被安全软件锁住）。

## 2. 一直显示「在线」但实际打不开网页（重要）

先看仪表盘「运行统计」里的 **探测方式** 一栏：

- 显示 **内容校验 + TCP 兜底** → 说明配置正常。如果这时还一直显示在线，就点「复制诊断信息」发出来，
  因为程序已经要求「真的取回指定网页文本」才算在线，出现这种矛盾多半是探测目标被学校网络特殊处理了；
- 显示 **仅 TCP 握手（可能被代答）** → 你（或旧配置）把 `ProbeTargets` 全设成了 `tcp:`。
  **有的校园网关会替任意 TCP 连接代答握手**（连不存在的地址也 0 ms「连上」），
  这种情况下程序永远判断不出掉线。请至少保留一个内容校验目标。

`ProbeTargets` 支持的写法：

```json
"ProbeTargets": [
  "http:connect.rom.miui.com/generate_204|204",
  "http:www.baidu.com/robots.txt|Baiduspider",
  "http:www.msftconnecttest.com/connecttest.txt|Microsoft Connect Test",
  "tcp:223.5.5.5:443"
]
```

| 写法 | 含义 |
| --- | --- |
| `http:主机/路径\|期望文本` | 内容校验：HTTP 2xx **且**响应体包含期望文本才算通过（`https:` 同样支持；3xx 一律算失败） |
| `http:主机/路径\|204` | 内容校验（只认状态码）：只有返回 204 才算通过；被校园门户劫持时通常回 200/302，一律算失败 |
| `tcp:主机:端口` | 只做 TCP 握手（便宜，但可能被网关代答） |
| `icmp:主机` | ping，很多网络禁 ICMP，只能当兜底 |

默认的四条是实测最稳的组合（微软 `connecttest.txt` 本机单次失败率约 10%，所以只当其中一条）。
如果哪一条在你的学校网络里常年不通，把它删掉或换成能取到内容的页面即可；至少留一条 `http:` 目标。

延迟显示的是**按配置顺序第一个成功目标**的耗时，不会再被 0 ms 的代答目标带到 0。
如果某个目标显示「（本地代答）」，说明它的 RTT 小于 5 ms，基本可以认定是本机/网关自己回应的。

另外，程序在线时默认每 60 秒会做一次**只读**的会话核对（`SessionCheckSeconds`，`0` = 关闭），
核对结果会写进「运行统计 → 会话校验」。如果连它都显示「Portal 显示已离线」，
程序会立刻走登录流程——不需要你手动点「立即重连」。

「会话校验」一行还会写明这次核对的来源：

| 来源 | 含义 |
| --- | --- |
| 定时巡检 | 到点自动做的常规只读核对，说明这个周期内一切正常 |
| 疑似掉线核对 | 本机探测（内容校验）没通过，程序主动向 Portal 求证。看到它说明本机探测已经不对劲了 |

2.1.0 起探测节奏整体加密：在线探测每 10 秒一次、定时巡检每 60 秒一次、
疑似掉线核对的最小间隔 10 秒（而且一轮内容校验没过就会去核对，不再要求连续两轮）；
插拔网线 / 切换 WiFi / IP 变化会立刻触发复检（日志里写作「网络变化事件（…）：已刷新网卡信息并立即复检。」）。
被踢下线后正常情况下 1 分钟内就会自动开始重连。

如果仪表盘显示「只有 TCP 握手、内容校验未通过」并且一直不变，程序会立刻补探一次，
补探还不过就去核对 Portal；核对完如果 Portal 也说在线，说明是残留会话（账号在线但数据出不去），
**连续 60 秒**后程序会自动注销后重新登录（等同手动「立即重连」）。

## 3. 状态是「连不上校园网，等待网络恢复」

说明本地探测和 Portal 都不通。这时候程序不会去登录（登录也没用），会每 3 秒重试。检查：

> 2.0.0-pre.7 起所有探测目标**并行执行**，HTTP 目标有独立的 3 秒超时，复检默认 2 轮 / 500 毫秒：
> 完全断网时从发现到提交登录通常十几秒（旧版本是串行等待，可能要几十秒）。
> 2.0.0 起提交登录前只等 1 秒（原来是 3 秒），而且会先做一次**纯本地内容校验**——
> 本地其实已经能上网时直接跳过登录，连 Portal 都不查。
> 嫌慢可以调小「高级设置 → HTTP 探测超时」，嫌敏感可以调大。

- 网线是否插好 / Wi-Fi 是否连上；
- 是否连到了错误的网络（例如手机热点或其它 Wi-Fi）；
- 本机是否开着会拦截流量的代理软件（Clash、VPN 等）。程序自身访问 Portal 时已显式绕过系统代理，
  但代理的 TUN 模式仍可能影响局域网访问。

## 4. 状态是「本机探测不通，但 Portal 显示账号在线」

这是上游异常（Portal 认为你在线，但实际数据出不去），常见于校园网侧故障或网卡驱动异常。
程序会转成按“兜底巡检”节奏复查（`UpstreamProbeSeconds`，默认每 300 秒一次），不会重复登录顶掉自己的会话。
可以手动试试点「立即重连」，或重插网线 / 重启网卡。

## 5. 状态是「已触发频率上限」或「登录提示已忽略，继续重试」

这两种情况都只是**本轮不再重试**，原因会写进仪表盘的「最近错误」和日志，程序会按节奏继续尝试：

- **Portal 明确限流（请求过于频繁）**：`error5 waitsec` / `Error code: 205`。程序会等过最小间隔
  （默认 60 秒）再试，并且每小时最多登录 12 次；如果频繁出现，说明同一账号在别处也在反复登录；
- **账号已在别处在线 / 密码错误（`userid error2` 等业务提示）**：2.0.0-pre.6 起**完全忽略**——
  不当成失败、不写「最近错误」，只累加「已忽略提示」计数并限频记一行日志，
  然后先**立刻**做一次本地内容校验（不发 Portal 请求），再按 +2 / +5 / +9 / +14 / +20 / +23 秒加密复检
  （每档只发一次**只读** `chkstatus`）：
  复检发现 Portal 已在线或内容校验通过，立刻算登录成功；确实不通就按最小间隔与每小时上限继续尝试。
- **真正的失败（login-failed）**：只出现在「连不上登录接口」或「收到完全无法识别的响应」时，
  这种才需要按下面第 6 节查。

节奏可以在 `config.json` 里用 `LoginMinIntervalSeconds`（两次登录最小间隔，默认 `60` 秒）与
`LoginHourlyLimit`（每小时上限，默认 `12` 次）调整；界面上的「高级设置」也能改。

2.0.0-pre.8 起 `RetryCount` 不再能绕过这两道闸门：它只决定「一次触发里最多提交几次」，
而且**每次提交前都要重新检查最小间隔与每小时上限**，不满足就直接停下（日志写「按最小间隔暂停重试」）。
另外每次真正提交的请求都会各自计入每小时窗口，次数不会再被少算。

## 6. 登录失败，日志里有 `Msg=…` 与错误码

程序会把 Portal 返回的 `msga` 送到错误码接口翻译成中文，常见含义：

| 错误码 | 提示 | 处理 |
| --- | --- | --- |
| `userid error1` | 账号不存在 | 账号写错了，或不在该认证域 |
| `userid error2` | 密码错误 / 账号已在线 | 先确认密码；如果密码没错，就是账号被占用（见上一节） |
| `error5 waitsec <3` | 请求过于频繁 | 刚注销完又立刻登录，等几秒 |
| `Error code: 205` | System Error1 | 多为请求过于频繁，程序会等过最小间隔再试 |

## 7. 杀毒软件 / SmartScreen 拦截

exe 是用仓库源码现场编译、没有数字签名的程序，火绒、Defender 可能首次运行就拦。
处理办法：在拦截提示里选择「允许 / 信任」；火绒可以在「防护中心 → 信任区」把
`CampusNet.exe` 或 `%LOCALAPPDATA%\Programs\CampusNet\` 加进白名单。

## 8. 开机后没有自动运行

检查三点：

1. 仪表盘的 **开机自动运行** 勾选框是勾上的；
2. 注册表 `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` 里存在 `CampusNet` 项；
3. 任务管理器的「启动」页里 `CampusNet` 没有被禁用。

如果之前用「绿色版」直接运行，自启项指向的是那个临时路径，移动文件后需要重新勾一次自启（或点一次「安装」）。

## 9. 想临时停止自动登录

托盘右键 → **暂停 30 分钟**（到点自动恢复），或者托盘右键 → **退出**（不自动恢复，需要手动打开）。

## 10. 彻底卸载

仪表盘点 **卸载**：会关闭开机自启、删除快捷方式，并移除安装目录里的 exe（数据默认保留）。
要连数据一起删，卸载后手动删除 `%LOCALAPPDATA%\CampusNet\` 即可。

2.0.0-pre.8 起卸载流程会**在提示后自己退出程序**：正在运行的 exe 无法就地删除，
所以程序会先写一个独立的清理脚本（`%TEMP%\CampusNet-cleanup-<PID>.cmd`），
等本进程退出后删掉 exe 并清理空的安装目录，同时登记「重启后删除」兜底——
所以不会再出现「弹窗说卸载了、文件还在、按钮又变回卸载」的自相矛盾。
只想看它打算删什么、不动任何文件，可以用：

```powershell
CampusNet.exe --uninstall --check-only
```

## 11. 后台悄悄消失 / 网络长时间不恢复

2.0.0-pre.6 起有守护进程兜底，正常情况下不会再出现「没人管」的状态。如果怀疑它崩过：

1. 看 `%LOCALAPPDATA%\CampusNet\crash.log` —— 有内容就是崩过，里面带完整堆栈；
2. 看 `%LOCALAPPDATA%\CampusNet\watchdog.log` —— 每一次「拉起 / 重启」都会记一行；
3. 确认守护还在跑：

```powershell
CampusNet.exe --status                     # 「守护：已开启（守护进程每 30 秒检查一次）」
CampusNet.exe --watchdog --check-only       # 打印判定（alive / stale / dead）与它会用的重启命令
```

如果显示「未开启」，用托盘图标右键 → **退出** 再重新打开一次程序即可（程序每次启动都会把守护拉起来）。

想再加一层（可选，需要管理员权限）：注册一个每 2 分钟跑一次的计划任务，等于给守护再加一道保险。
在**管理员** PowerShell 里执行：

```powershell
schtasks /create /f /tn CampusNetWatchdog /tr "\"$env:LOCALAPPDATA\Programs\CampusNet\CampusNet.exe\" --watchdog" /sc minute /mo 2
```

它和守护进程互不冲突：都只是「看看进程在不在、不在就拉起来」。

## 12. 需要更深入的排查

```powershell
# 当前状态一行行打印
CampusNet.exe --status

# 完整诊断（版本、路径、网络、配置、状态、旧版残留、日志尾部）
CampusNet.exe --diagnose --with-log

# 前台跑一轮完整检查（会真实探测，必要时登录）
CampusNet.exe --once

# 界面自检：构建窗口、刷新一次后退出
CampusNet.exe --selftest

# 删除历史日志文件（login.log / login.log.old，只留一行「日志已清空」）
CampusNet.exe --clear-log

# 守护自检：什么都不改，只打印 alive / stale / dead
CampusNet.exe --watchdog --check-only
```

日志文件：`%LOCALAPPDATA%\CampusNet\login.log`（超过 5 MB 自动滚动为 `login.log.old`），
另有 `crash.log`（崩溃堆栈）与 `watchdog.log`（守护动作）。
界面上的「运行日志」卡片右上角是 **清除显示** 按钮：它只清空窗口里的日志显示、
**不删除也不截断** `login.log`（所以不需要二次确认，点完会写一行
「显示已清除（本机日志文件未删除…）」）。要真正删掉历史日志文件请用上面的 `--clear-log`。
「运行日志」卡片右上角还有一个 **跟随最新** 勾选框（默认勾选）：勾着时新日志会自动滚到底，
取消勾选后你往上翻看历史就不会被强行拉回去了。
高级设置已经移到**单独的窗口**（「程序」卡片 → 高级设置），里面的输入框**改完即自动保存**
（点开别处或按回车生效），没有单独的保存按钮；
填了超出范围的值会自动回退，并在下方显示该项目的允许范围。

## 13. 状态是「登录已提交，等待确认」

登录接口回了成功，但紧接着 Portal 的**状态接口不可达**（例如 Portal 自己在重启或抖动）。

2.0.0-pre.7 起这种情形**不再记成登录成功**：旧版本会把它记成 `login-ok`，然后很长时间不再重试，
网络就一直不恢复——这正是「明明掉线了却一直不自动登录」的原因之一。现在会记为「待确认」
（`login-unconfirmed`，黄色）并继续按异常节奏复检，同时**不写**「登录成功」时间。

如果这个状态只是偶尔一闪，等 Portal 恢复就好；如果长期停留，多半是 Portal 侧不稳定，
可以看日志里的「状态接口不可达」后面的具体原因。

## 14. 状态是「配置文件损坏」/「探测目标配置无效」

这两种情况程序都会**主动停下来不登录**，这是有意设计的：

- **配置文件损坏（`config-invalid`）**：`config.json` 解析不了（半截 JSON、空文件等）。
  旧行为是直接退回默认配置继续跑——你自定义的 Portal 地址一旦丢失，账号密码就可能被发到
  默认地址去。现在会停下来提示。处理办法：打开 `%LOCALAPPDATA%\CampusNet\config.json` 改好，
  或者直接在界面「高级设置」里改任意一项并保存（会写回一份完好的配置）。
  写入本身是「临时文件 + 原地替换」，正常情况不会写出半截文件。
- **探测目标配置无效（`probe-config`）**：`ProbeTargets` 里没有任何一条合法目标，
  程序无法判断网络状态——既不冒充当「在线」（那会让自动登录永远不触发），
  也不拿着坏配置反复去问 Portal。请按下面的格式修好至少一条。

合法写法（大小写不敏感）：

| 写法 | 含义 |
| --- | --- |
| `http:主机/路径\|期望文本` | HTTP 2xx 且响应体包含该文本才算通过（`https:` 同样支持） |
| `http:主机/路径\|204` | 只认状态码 204（专治「被劫持时返回 200 门户页」） |
| `http:主机/路径\|期望文本\|204` | 两个条件都要满足 |
| `tcp:主机:端口` / `icmp:主机` | 只证明「连得上」，作为兜底 |

## 15. 用命令行保存账号密码

密码**不再接受命令行参数**（`--set-credentials 账号 密码` 会留在 PowerShell 历史、
进程列表和审计日志里，也会被 `--set-credentials` 直接拒绝并返回退出码 2）。两种安全写法：

```powershell
CampusNet.exe --set-credentials 你的账号                  # 提示输入密码，输入不回显
'你的密码' | CampusNet.exe --set-credentials 你的账号 --password-stdin
```

最省事的还是打开界面在「账号」卡片里填写——密码用 DPAPI 加密后存盘，只有当前 Windows 用户能解密。
协议层面的细节（接口、字段、编码、错误码来源）见 [Dr.COM ePortal 协议说明](DRCOM-PROTOCOL.md)。

## 16. 学校要求密码用 MD5 加密提交（`en_md5=1`）

Dr.COM ePortal 有明文与 MD5 两种提交方式（`en_md5=0` / `en_md5=1`）。
**本工具只实现了明文提交**（`en_md5=0`），如果学校强制 `en_md5=1`，登录会一直失败：

- 日志里会出现「`userid error2` / 密码错误」这类业务提示，后面跟一行
  「本工具按明文提交（相当于 en_md5=0），若学校要求 en_md5=1 会一直失败」；
- 界面「运行统计 → 已忽略提示」计数会持续增长。

遇到这种情况没有配置项可以打开——请换用学校提供的官方客户端或网页登录。
想自查的话，可以打开浏览器的开发者工具，看学校登录页提交的字段里
是否带 `en_md5=1`：带了就是这个原因。

## 17. 日志 / 状态文件里会不会出现密码

不会。2.0.0-pre.8 起有一个统一的脱敏入口，**所有可能落盘的文本**在写出前都会处理：

| 位置 | 处理 |
| --- | --- |
| `login.log` / `login.log.old` | 写入前脱敏 |
| `state.json`（`LastError` / `LastMessage` / `LastIgnoredPrompt`） | 写入前脱敏 |
| 界面「复制诊断信息」、`--status`、`--diagnose` | 读的就是上面两处，自动跟着干净 |

规则：密码一律替换成 `***`（含 URL 编码后的 `Upass=…` 形态），账号只保留前三位，
例如 `202312345` 显示成 `202******`。内存里的真实密码不动，登录功能不受影响；
`credentials.dat` 仍是 DPAPI 加密文件。

如果你在用**旧版本**（pre.7 及以前）并且在日志里看到过完整密码，
可以点 `CampusNet.exe --clear-log` 把历史日志文件删掉（界面上的「清除显示」只清空窗口显示，
不会删除 `login.log`，别把两者搞混）。

## 18. 状态是「等待下次登录（正在本地监视网络恢复）」

这是 2.0.0-pre.10 起的正常状态，说明程序**刚刚提交过一次登录**，还没到「两次登录至少间隔 60 秒」的
硬性最小间隔，所以这一轮不能重复登录。老版本在这段时间会直接睡满剩余秒数（本机实测最多浪费 33 秒），
现在改成每约 3 秒**只做本地探测**：

- 这段时间**一个 Portal 请求都不发**（既不是 `chkstatus` 也不是 `login`），所以对风控更友好；
- 网络一恢复，日志会写「最小间隔等待期内检测到网络恢复（本地探测通过，未发 Portal 请求）」，
  状态立刻回到「在线」——通常最多几秒；
- 如果网络一直没恢复，等过了最小间隔，程序会按正常节奏再登录一次（每小时最多 12 次）。

看到这个状态只需要等一会儿；如果它停留超过 1 分钟且网络确实不通，再按第 5 节检查
「已忽略提示 / 频率上限」，或者点一次「立即重连」。
