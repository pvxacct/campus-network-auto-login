# CampusNet 恢复优化实施设计

本设计根据已批准的「速度与稳定兼顾」方案实施。基线为 a8efaa09ad672bad9f175eb8ac446028927e0291（2.1.2）；交付为 2.2.0-pre.1 预发布。

## 问题证据

CampusNet.zip 的 137 次带耗时登录请求均在 0.4 秒内返回；2.1.2 六次完整提交到记录恢复为 29、16、6、36、23、16 秒，中位数 19.5 秒。日志未记录外网实际可用时刻，不能推导真实确认延迟。
基线源码存在恢复探测与会话请求串行叠加、会话在线冒充联网恢复、注销先于限频、重载覆盖实时计数、上游分支整轮等待 300 秒等问题。

## 观察窗口与判定

保留默认在线 20 秒、异常 5 秒、周期会话核对 120 秒。登录响应后立刻进入实际 30 秒窗口；单轮内容校验每 2 秒安排一次，最多一个在途任务。Portal 独立在第 2、5、9、14、20、23 秒查询，最多六次，慢请求错过档位跳过。
配置了 HTTP 目标时，任一取得预期内容或状态码即通过，取消其余；未完成目标不记失败。无 HTTP 的旧配置须探测通过且会话在线，明确提示未验证内容。窗口结束仍按异常频率检查。

## 取消、状态与资源

每轮探测有整体截止时间；私有结果在截止后不更新已返回结果。暂停、退出、重载通过取消与代次检查使旧流程失效。
探测全进程最多八个工作任务；状态查询最多两个存活任务以限制取消后极端 DNS 延迟的资源占用。当前窗口各类只允许一个在途任务。
上游分支仍做本地异常监测；300 秒仅限制全部探测失败时的会话查询。
原子状态保存串行化，读取允许替换；替换失败不删除有效旧文件。

## 登录闸门

所有入口统一检查有效凭据、暂停、最小间隔和小时上限，通过后才允许注销。默认保留登录前 1 秒确认、最小 60 秒、每小时 12 次。按每次提交登记尝试并在请求前持久化；进程被打断时可保守多占一次额度。
残留会话阈值沿用已有配置，同一次未恢复故障最多自动重登一次；恢复后清除标记。热重载仅应用配置和凭据，保留实时计数。

## 测试与交付

并发本地假 Portal 覆盖立即恢复、延迟 5/15/30/60 秒、慢内容、Portal 超时/滞后、TCP 假在线、暂停取消、重载计数、统一限频和一次故障最多自动注销一次。
默认超时且成功目标响应不超过 200 毫秒时，联网可验证后观察窗口内 4 秒内、后续等待期 6 秒内确认。兼容测试继续覆盖旧 CLI、配置迁移和业务响应。
保持 C# 7.3 / .NET Framework 4.8、已有配置键与 CLI；以 .NET 8 SDK 编译。交付源代码 ZIP、单文件 EXE、SHA256 文件和证据/测试报告。
实机验收用自然掉线，分别记录 POST 时间和提交到验证通过时间，不把模拟测试作为实机速度提升结论。
