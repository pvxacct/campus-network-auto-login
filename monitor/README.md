# 校园网监控面板

这是一个**独立运行、完全只读**的 Windows 桌面小窗口，用来随时看一眼「校园网自动登录」到底在做什么。
它配合 [campus-network-auto-login](https://github.com/pvxacct/campus-network-auto-login) 使用，
但和自动登录包**分开打包**，可以放在任何地方，删掉自动登录包也不影响它启动。

界面从 2.0.0 起用 WPF 重写：浅色现代风格，圆角卡片、自绘标题栏、延迟迷你折线图与连通状态时间线。
还是老规矩——系统自带的组件，不需要额外安装任何东西。

## 它做什么、不做什么

- ✅ 读取 `%LOCALAPPDATA%\CampusAutoLogin` 里的 `state.json` 与 `login.log`（只读日志末尾 512 KB）；
- ✅ 读取计划任务 `CampusAutoLogin` 的状态、上次运行时间、返回码、下次运行时间；
- ✅ 顺藤摸瓜检查「计划任务 → 隐藏启动器 → 主脚本」三个文件是否都还在；
- ✅ 显示本机 IP、网卡、默认网关、DNS、网络类型，以及到**网关**和 **Portal** 的延迟与丢包；
- ✅ 把延迟画成折线趋势、把最近 60 次刷新的结论画成一排色块（数据只在内存里，不落盘）；
- ✅ 从日志里统计最近 24 小时的登录次数、成功/失败、限流、重复认证冲突与掉线次数；
- ❌ 不创建、不修改、不删除任何文件；
- ❌ 不注册计划任务、不写启动项、不常驻托盘；
- ❌ 不向 Portal 的**登录接口**发任何请求。全部网络行为只有两种：
  1. 默认每 10 秒一次 **ICMP ping**（到默认网关和 Portal 各一发，用来算延迟和丢包）——
     这是操作系统层面的连通性探测，不走 HTTP、不碰 `/drcom/login`，不会影响账号风控；
     不需要的话把 `monitor-config.json` 里的 `PingEnabled` 改成 `false` 即可完全静默；
  2. 你手动点「立即检查一次」时，才向 Portal 发一次只读的 `GET /drcom/chkstatus`
     （相当于问一句“现在在线吗”，不会登录、不会写状态文件）。

## 运行要求

- Windows 10 / 11，系统自带的 Windows PowerShell 5.1 与 .NET Framework 4.x（都是系统自带，不需要额外安装）；
- 普通权限即可，不需要管理员；
- 如果自动登录装在别的 Windows 用户下，面板读不到数据目录，需要用 `-DataDir` 指过去。

## 怎么用

1. 解压压缩包，得到一个文件夹；
2. 双击 **`启动监控面板.vbs`**（推荐，完全没有黑框），或者双击 `启动监控面板.cmd`（会留一个命令行窗口）；
3. 窗口每 5 秒自动刷新一次，看完直接点「关闭」。

也可以命令行启动，方便排查问题：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\CampusNetworkMonitor.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\CampusNetworkMonitor.ps1 -DumpOnce     # 不开窗口，打印一次状态
powershell -NoProfile -ExecutionPolicy Bypass -File .\CampusNetworkMonitor.ps1 -SelfTest     # 冒烟测试：建窗口、刷新一次、退出
powershell -NoProfile -ExecutionPolicy Bypass -File .\CampusNetworkMonitor.ps1 -DataDir "D:\somewhere\CampusAutoLogin"
```

## 窗口里有什么

| 区域 | 内容 |
| --- | --- |
| 标题栏 | 自绘的窗口标题栏：左边是徽标与版本号，右边是最小化／最大化／关闭；拖动、双击最大化、缩放、贴边都照常 |
| 顶部横幅 | 一句话结论，颜色区分：灰=没装/未知，红=有问题，橙=冷却中，黄=正在重连，绿=一切正常；右边显示本次刷新时间 |
| 指标卡片 | 四张卡：「运行状态」「计划任务与路径体检」「网络」「数据与统计」，共 25 项指标，异常值按红／黄着色 |
| 延迟趋势 | 到网关／Portal 的延迟折线（丢包位置标红点），右上角图例显示每个目标的当前延迟 |
| 连通状态 | 最近 60 次刷新的结论，一格一次，颜色与顶部横幅一致 |
| 路径体检 | 「计划任务 → 隐藏启动器 → 主脚本」三步逐个检查，任何一步的文件或起始目录不见了就红字提示「僵尸任务」 |
| 日志区 | `login.log` 的最近 200 行，等宽字体，警告橙色、错误红色，可勾选「只看警告和错误」 |
| 底部操作栏 | 立即检查一次 / 刷新 / 打开数据目录 / 复制诊断信息 / 关闭，右边显示数据目录与版本号 |

最后，如果你想联网检查一下：点「立即检查一次」——它只发一次状态查询，按钮随后禁用 5 秒防止手快连点。

## 配置（`monitor-config.json`）

文件是可选的，缺省或删掉都能跑。所有键都有默认值：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `RefreshSeconds` | `5` | 界面自动刷新间隔（秒） |
| `StatsWindowHours` | `24` | 统计窗口小时数 |
| `PortalHost` | `""` | Portal 地址，留空则自动解析（见下） |
| `StatusPath` | `/drcom/chkstatus` | 状态查询路径 |
| `StatusTimeoutSec` | `8` | 「立即检查一次」的超时秒数 |
| `DataDir` | `""` | 数据目录，留空则用 `%LOCALAPPDATA%\CampusAutoLogin` |
| `PingEnabled` | `true` | 是否做延迟探测（`false` 则完全不发 ICMP，网络区只显示 IP／网关／DNS） |
| `PingIntervalSeconds` | `10` | 延迟探测间隔（秒） |
| `PingTimeoutMs` | `1000` | 单次 ping 超时（毫秒） |
| `PingTargets` | `"gateway,portal"` | 探测对象，可写 `gateway`、`portal` 或两者 |
| `LatencySamples` | `10` | 延迟统计保留最近多少次采样 |
| `NetworkInfoSeconds` | `20` | 网卡信息缓存秒数（避免频繁查询） |
| `SparklinePoints` | `60` | 延迟折线图保留多少个采样点（按 `PingIntervalSeconds` 折算时间跨度） |
| `TimelinePoints` | `60` | 连通状态时间线保留多少格（按 `RefreshSeconds` 折算时间跨度） |

Portal 地址的解析顺序：

1. 计划任务指向的主脚本所在目录里的 `drcom-config.json`（也就是自动登录真正在用的那个地址）；
2. 面板自己的 `monitor-config.json` 里的 `PortalHost`；
3. 内置默认值 `10.66.209.2`。

## 常见问题

**横幅显示「脚本未在运行」？** `state.json` 超过 180 秒没更新，说明计划任务没在跑。看「路径体检」那一行：
如果是红色的「僵尸任务」，说明安装目录被删/被移走了，把文件夹放回原位或者重新运行一次一键安装即可。

**指标区显示「没有找到计划任务」？** 自动登录还没安装，或者装在了另一个 Windows 用户下。

**日志是空的？** 还没生成 `login.log`（脚本只在真的要检查/登录时才写日志），等它跑一次就好了。

**IP／网关显示「读不到网卡信息」？** 面板用的是系统自带的 .NET 网卡接口，普通权限就能读；
如果确实读不到，多半是网卡处于禁用状态或驱动异常。**网络类型**这一行需要 CIM 支持，
个别受限账户下会显示「读不到网络名称」，不影响其它信息。

**网关延迟显示「无响应」？** 有些路由器默认不回应 ICMP，这一项无响应并不代表网络有问题，
看 Portal 那一项更准。

## 与主包合并的约定

面板原本计划并进自动登录的主包；实际合并最终由 2.0 以「单文件 exe」的形式完成，1.x 这边两个包继续分开下载。当初定下的约定如下（1.x 仍然遵守）：

1. **位置**：面板文件整体放在主包的 `monitor\` 目录下，入口固定为 `monitor\启动监控面板.vbs`；
2. **不依赖自身路径**：Portal 地址按「计划任务动作链指向的主脚本目录里的 `drcom-config.json`
   → 面板自己的 `monitor-config.json` → 内置默认值 `10.66.209.2`」解析；所以面板放在哪个目录、
   是不是和主脚本同目录，都能正常工作；
3. **永远只读**：面板不创建、不修改、不删除任何文件，也不注册计划任务；放进主包不会影响自动登录的任何行为；
4. **入口可调用**：主包将来只需在一键安装脚本末尾加一句可选的「是否打开监控面板」，
   调用 `monitor\启动监控面板.vbs` 即可，面板代码不用改；
5. **测试约定**：数据层函数名、`-DumpOnce` 输出格式与脚本里 `# ===================== 入口` 这条分界线
   保持稳定，自动化测试可以直接复用。

## 版本

面板自身版本 `2.0.0`，随自动登录 `v1.9.0` 一起发布，窗口标题会同时显示两者。
默认约定：主脚本版本低于 `1.5.1` 时，「已安装脚本版本」会标黄提醒升级。
